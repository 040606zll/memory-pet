# 宠物名字冲突测试用例

| 层次 | 场景与断言 |
| --- | --- |
| 模型协议 | 羊狗、团团、首尾空格、空值、非法类型、超长和控制字符；非法可选值不丢失有效正文 |
| 实际 Agent + HTTP 替身 | 训练/正式 × 宠物/普通页面；名字随消息保存，仅宠物页返回，训练仍为待确认候选，无自动 ingest |
| 幂等重放 | 已完成响应保留名字，不再调用模型或召回 |
| 前端同步 | 回复名字更新页面和下一请求，省略/非法/失败不重置名字 |
| 前端一致性 | 标题、问候、等待、头像、画布与互动标签同步，改名不重载动画 |
| 前端隔离 | 按账号缓存，旧全局昵称不泄露给新账号，旧历史不回滚名称，手动改名不被迟到响应覆盖 |
| 真实模型 | 当前起名、空历史召回名字、新名字覆盖旧名字、用户与宠物名字区分、本会话新名字不被旧记忆回滚 |
| 浏览器隔离页面 | 输入“你叫羊狗”，标题成为“教羊狗更懂你”；切换正式对话，下一条回复仍用羊狗，布局保持一致 |

后端用例：`tests/backend/bug_fix/2026-10-15/宠物名字冲突/test_pet_name.py`。

前端用例：`frontend/tests/app.test.jsx`、`robotDog.test.jsx`。浏览器页面：`frontend/tests/pet-name-visual.html`，业务接口为替身，不访问模型、MySQL 或 MemoryOS。

真实模型脚本：`python -B tests/backend/bug_fix/2026-10-15/宠物名字冲突/run_live_model.py --run-live`。显式运行时调用当前后端配置的模型五次，使用专用测试句和构造记忆，不访问 MySQL、MemoryOS，也不打印凭据。输出到同目录文档下的真实模型验证.json。

部署后使用专用测试账号依次验证训练起名、确认命名候选、新建正式对话召回及切换账号；该流程涉及真实数据库与 MemoryOS，应在专用环境执行。
