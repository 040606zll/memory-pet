# MySQL 库名误拦截测试用例

## 复现入口

通过真实启动配置入口 `DatabaseConfig.from_settings()` 传入横线或中文库名，无需数据库即可复现启动时的配置错误。修复前已执行最初的回归用例，结果为 16 项失败、3 项通过。

## 回归范围

| 场景 | 预期 |
| --- | --- |
| 横线、中文、中文横线混合库名 | 配置通过且原样保留 |
| 64 字符库名、保留字、纯数字库名 | 配置通过 |
| 分号、反引号、`@`、内部空格 | 作为数据库连接参数原样传递 |
| 驱动连接参数生成 | database 值不变，连接池没有取得连接 |
| 空库名、超过 64 字符 | 拒绝且提示 mysql.database |
| 库名含路径分隔符、点、尾随空格 | 拒绝且提示 mysql.database |
| 库名含 NUL、表情等扩展字符、代理码位 | 拒绝且提示 mysql.database |
| host/user 为空、仅空格或 None | 拒绝并提示对应配置字段 |
| 错误提示 | 不出现密码标记 |
| 原有数据库层契约 | MySQL 限制、端口、事务、连接池、错误包装和取消清理继续通过 |

## 执行方法

在项目根目录使用已安装依赖的 Python 环境运行：

```bash
python -B -m pytest tests/backend/bug_fix/2026-10-15/MySQL库名误拦截 tests/backend/test_mysql_database.py -q --cov=pet.database --cov-report=term-missing
```

这些用例不调用数据库、不建表、不修改真实配置，也不调用模型或记忆服务。
