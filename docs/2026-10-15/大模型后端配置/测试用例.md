# 大模型后端配置：测试用例

日期：2026-10-15。

| 用例 | 操作与预期 |
| --- | --- |
| 仅服务端模型 | 设置三项测试 `LLM_*` 环境，页面只提交 MemoryOS；验证模型请求使用服务端地址、Key、名称 |
| 禁止页面覆盖 | 分别提交 `llm`、`llm_url`、`llm_key`、`model`；均为 422、无上游调用、当前配置不变 |
| 缺少服务端配置 | 逐项移除三项 `LLM_*`；均为 428，提示联系管理员，无上游请求 |
| 状态最小公开 | 配置及连接状态响应的 `llm` 只有 configured，不含模型 URL、Key 或名称 |
| 断开后重连 | 断开清除记忆 Key、保留模型三项；重新提交 MemoryOS Key 后验证成功 |
| 更换记忆连接 | 改 MemoryOS 地址／路径／用户，不覆盖服务端模型；跨来源不继承旧记忆 Key |
| 失败保留原连接 | 上游验证失败不替换当前配置；敏感请求字段不回显 |
| 宠物页表单 | 只有三个 MemoryOS 字段、一个密码输入；提交体只有 memoryos，浏览器不保存 Key |
| 普通对话页表单 | 共用弹窗，无模型地址、密钥、名称输入；提交体只有 memoryos |
| 现有业务回归 | 训练、候选编辑和确认、跨会话召回、模式隔离、取消及重试等现有用例均通过 |

自动化入口：`tests/backend/test_api.py`、`tests/backend/test_memory_surface.py`、`frontend/tests/app.test.jsx`、`frontend/tests/memoryChat.test.jsx`。真实上游由 httpx 传输替身模拟，不写入正式记忆。

手工验收：两页分别打开连接弹窗，确认无模型输入；由管理员配置并重启宠物后端后，提交 MemoryOS 验证连接，再使用专属测试用户验证训练与正式对话。真实验证会产生模型调用，训练记忆仅确认后落入 MemoryOS。
