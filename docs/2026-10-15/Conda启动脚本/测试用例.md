# Conda 启动脚本测试用例

测试文件：`tests/backend/test_start_script.py`。使用临时项目和 Conda 替身，避免读取开发者密钥、访问上游或影响正在运行的服务。

| 场景 | 预期 |
| --- | --- |
| 默认命令、显式 start | 使用 xyd，调用同目录 start_service.py，不依赖根目录 scripts，不传建号或轮换参数 |
| 带空格的路径及其他工作目录 | 正确定位项目和入口 |
| run、修改脚本中固定的环境名和路径 | 进入 backend 目录，调用 run.py，使用脚本中的环境名 |
| --help、-h | 无需有效 Conda，不启动服务 |
| 不支持的命令、额外参数 | 返回 2，无启动行为 |
| 固定 Conda 路径不存在、为目录或相对路径 | 返回 1，不回退系统 Python |
| 固定环境名为空 | 返回 1，不启动服务 |
| 系统设置 CONDA_EXE、PET_CONDA_ENV | 忽略这两个变量，仍使用脚本固定配置 |
| Conda 环境或命令失败 | 保留错误码，补充中文提示 |
| 真实 xyd，8797 已占用 | 原启动器拒绝重复启动，不替换现有进程 |

可运行 `bash -n backend/start.sh` 检查语法，使用 `python -m pytest tests/backend/test_start_script.py -q` 验证新入口。首次成功启动完整服务需在空闲 8797 的独立环境执行，再检查 `/api/health`、PID 和后台日志；本轮没有停止现有服务执行该项。
