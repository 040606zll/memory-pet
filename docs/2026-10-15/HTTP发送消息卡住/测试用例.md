# HTTP 发送消息回归用例

| 场景 | 断言 |
| --- | --- |
| 宠物页训练/正式对话，randomUUID 缺失 | 创建会话并调用聊天接口一次，request_id 为 UUID v4，收到回答后恢复输入 |
| 普通记忆页写入/召回，randomUUID 缺失 | 调用聊天接口一次并释放操作锁 |
| 两页面全部随机数能力缺失 | 展示中文错误，不发送会话/聊天请求，草稿保留且可切换模式 |
| 原生 randomUUID 可用 | 复用原生实现 |
| 仅 getRandomValues 可用 | UUID 版本与变体正确，100 个编号无重复 |
| 失败重试、取消、候选确认 | 保持既有用例与接口语义 |

命令（从项目根目录执行）：

```bash
python backend/tests/bug_fix/2026-10-15/HTTP发送消息卡住/reproduce.py
npm --prefix frontend run test:coverage -- --reporter=dot
npm --prefix frontend run build
npm --prefix frontend run test:sites
```

前端组件测试模拟浏览器在 HTTP 下缺少 randomUUID 的能力状态，并通过 fetch 替身核对实际组件发起的请求。不是对线上用户记忆的真实写入验收。
