# API Key 与用户自动绑定

日期：2026-10-15。适用于宠物页和普通记忆页，共用宠物后端。

## 连接接口

`POST /api/connection` 请求：

```json
{"memoryos":{"base_url":"http://127.0.0.1:8863","api_key":"<实际Key>"}}
```

页面不再提交用户 ID。接口保留可选 `memoryos.user_id` 以兼容固定用户，但必须属于当前 Key，且不能覆盖已有绑定。未更换服务来源时可用空 Key 保留当前进程的 Key；重启后没有服务端 Key 配置时仍需填写。

成功返回既有状态结构，`data.memoryos.user_id` 为实际远端 UUID，`connected=true` 表示模型与记忆权限均已验证。不会向页面返回任何密钥。模型仍只由宠物后端配置。

## 绑定规则

1. 检查模型配置与 MemoryOS 就绪状态。按用户后续要求已移除匿名目录前置检查，不再因匿名 `/users` 可读返回 409。
2. 用提供的 Key 分页读取用户目录，取得 MemoryOS 返回的稳定 `api_key_id`。
3. 优先使用 SQLite 已保存的一对一绑定；没有绑定时可使用固定 UUID，或复用 Key 名下唯一用户。
4. Key 名下已有多个用户时，恢复名为 `MemoryPet 专属用户` 的唯一专属用户；不存在时创建。多个同名记录则停止连接，不随机选择。
5. 校验用户详情中的归属、active 状态；模型验证成功后才可能创建用户。创建调用 `POST /users`，由 MemoryOS 生成 UUID，并显式关闭知识库权益。
6. 验证该用户记忆接口权限后，在短事务中持久绑定并替换当前连接；网络调用期间不持有数据库事务。

固定对应关系保存在宠物 SQLite 的 `memory_user_bindings`：同一服务地址下，一个上游 Key 标识对应一个用户，用户也只能绑定一个上游 Key 标识。正常 Key 轮换不改变上游 Key 标识，因此不会重新建号。断开不删除绑定，重启后仍可复用。

本项目不改变 MemoryOS 一个 Key 可管理多个用户的原有规则；一对一约束限定宠物项目的使用关系。同一 Key 连接同一宠物后端意味着同一份用户记忆。本版仍只支持单进程单受信任使用者，不提供访客登录隔离或跨多个副本的首次建号幂等承诺。

## 错误与恢复

| 情况 | 行为 |
| --- | --- |
| Key 无效或没有用户目录权限 | 中文错误，不创建用户、不更换当前连接 |
| 目录匿名可读 | 不探测、不据此拦截，继续携带 Key 验证；公网 MemoryOS 仍需 production |
| 用户额度用尽 | 422，提示管理员调整额度 |
| 固定用户不属于 Key、用户停用或请求换绑 | 409，不自动替换其他用户 |
| 上游缺少有效 UUID／Key 归属字段 | 502，停止绑定 |
| 创建成功但响应丢失 | 原请求报错；重试先查询远端目录和专属标记，恢复已有用户，不盲目重复 POST |
| 模型或记忆验证失败 | 不替换当前进程连接；远端已创建用户可由下次连接恢复 |

本地备份必须包含绑定表。迁移 SQL 位于 `backend/sql/{sqlite,postgresql,mysql}/003_memory_user_bindings.sql`，Alembic 版本为 `20261015_003`。当前实际运行的数据库仍为 SQLite，其他数据库 SQL 不代表已实现运行时适配。

2026-10-15 后续调整：删除目录匿名访问预探测，不代表新增 Key 身份验证。上游不隔离目录时，返回的归属字段不足以证明目录属于传入 Key；本项目仍只供单受信任用户使用。详细更新说明见[移除匿名目录前置检查](../移除匿名目录前置检查/API接口文档.md)。
