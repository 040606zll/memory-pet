## 强制鉴权预检的环境阻塞

用户已确认仅在当前 MemoryOS 启动环境设置 AUTH_ENFORCED=true 并重启，不修改 .env。实际重启前，使用原进程相同环境加入该值调用 MemoryOS 的 assert_production_ready，预检未通过：KB_VISION_MODE=mock；AUTH_SECRET 仍是默认值。后续只读检查确认 MinerU Key 未配置。

因此没有停止或重启原 MemoryOS，没有修改 .env、签名密钥、模型供应商配置或跳过校验。需要管理员先补齐独立 AUTH_SECRET 与真实 MinerU 配置，才能继续启用鉴权并验证真实 Key 自动绑定。自动化完整链路使用契约替身通过，当前本机真实绑定成功尚未验收，不能把隔离拦截成功描述为绑定成功。

## 风险与后续验收

自动创建会消耗一个上游用户额度；失去本地库时优先恢复远端专属标记，有歧义则停止。当前只保证一个受信任使用者、一个后端进程内的串行建号，不支持多个独立副本并发初始化。保存明文 Key 的方式仍为进程内或管理员配置，不保存浏览器；本地绑定只存上游标识和 UUID。

生产环境仍需 MEMORYOS_PROFILE=production。MySQL、PostgreSQL SQL 已提供但未对真实对应数据库执行；宠物运行时保持 SQLite。没有变更 MemoryOS 核心代码、鉴权代码、依赖或实际凭据，没有提交 Git。
