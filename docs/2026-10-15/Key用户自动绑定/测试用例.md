# Key 用户自动绑定测试用例

日期：2026-10-15。主要入口 `tests/backend/test_connections.py`。

| 场景 | 预期 |
| --- | --- |
| 首次 Key 无用户 | 创建一次真实响应形状的远端用户，使用返回 UUID，落入本地绑定 |
| 重连、断开后重连、重建应用 | 复用同一用户，POST 建号次数仍为 1 |
| Key 已有唯一用户 | 直接复用，不新建 |
| Key 有多个用户 | 首次创建或恢复唯一专属用户，本地绑定存在时不受目录排序变化影响 |
| Key 轮换 | 稳定 api_key_id 复用原用户及会话历史 |
| 更换另一个 Key | 使用另一个用户，旧 Key 会话不在新 scope 中可见 |
| 请求覆盖已有绑定 | 409，不换绑 |
| 并发连接 | 单个后端进程内只有一次远端创建，两次请求返回相同 UUID |
| 创建后响应丢失 | 首次超时，重试恢复已创建用户，不重复建号 |
| 无效 Key、缺 Key、缺模型、模型失败 | 不创建用户 |
| 用户配额不足 | 中文额度提示，不修改原连接或插入绑定 |
| 用户停用或固定用户缺失 | 不静默创建替代用户 |
| 专属用户歧义 | 明确报错，不选随机记录 |
| 缺 UUID 或 Key 所有者字段 | 拒绝绑定 |
| 目录中其他停用用户排在首位 | 有效固定用户仍可正常连接 |
| 匿名用户目录可读 | 不发起匿名预探测；携带 Key 继续连接，响应字段有效时成功 |
| SQLite 唯一约束 | 同一 Key 不能绑定多个用户，同一用户不能绑定多个 Key |
| 迁移重放及旧会话 | Alembic 重放安全；旧数据库升级测试继续保留历史 |
| 前端两种页面 | 只有地址和 Key 输入，不提交 user_id，不存浏览器密钥 |

自动化 HTTP 使用传输替身和临时 SQLite，不写入真实用户或记忆。真实验收需有有效用户归属响应、真实模型配置和足够用户额度。匿名目录预探测已按后续要求删除，相关回归见 tests/backend/bug_fix/2026-10-15/移除匿名目录前置检查/；MemoryOS 公网生产鉴权部署要求保持。
