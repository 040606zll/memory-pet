# 公网来源 403：服务器更新步骤

适用当前服务器 `81.71.39.10`、前端 `API_BASE_URL='/pet-api'`、后端仅监听 `127.0.0.1:8797` 的单用户部署。本次不会修改 MemoryOS 的权限、API Key 或用户绑定逻辑。

## 1. 更新文件

进入服务器上包含 run.py、config.toml、pet/ 的实际后端目录，当前用户提供的路径为：

```text
/root/www/server/memory-pet/backend/backend/
```

上传并替换 `pet/main.py`、`pet/settings.py`，新增 `pet/access.py`。可将交付的 `public-access-fix.zip` 解压到此目录，包中只含这三份代码、白名单示例、Nginx 示例和本文。建议先将被替换代码备份到网站目录之外。

不要将修复包解压到前端网站目录。包内没有真实 config.toml、config.local.toml、启动脚本或密钥，不会覆盖服务器的 Conda 路径和 memory 环境名。服务器的三个 Python 文件必须一起更新，避免旧加载器拒绝新配置或缺少 access 模块。

## 2. 先保护 Nginx 公网入口

本次白名单用于校验部署地址，不是用户登录；非浏览器客户端可自行填写 Host 和 Origin。应用仍为单进程、单受信任用户，配置的 MemoryOS Key 和会话不是按访问者隔离。因此公网放行白名单前，须先通过 HTTPS 和 Nginx 站点账号密码保护整个站点，后端 8797 继续只监听回环，不对外开放。

站点账号密码由管理员在服务器自行设置，不通过聊天传递，也不放入前端、MemoryOS Key 字段或模型配置。若服务器已有 htpasswd 工具，首次创建不存在的专属密码文件时可执行：

```bash
htpasswd -c -B /www/server/nginx/conf/memory-pet.htpasswd petowner
```

按终端提示输入密码；密码文件必须位于网站目录之外，且仅允许管理员修改、Nginx 运行用户读取。文件已存在时不要使用 `-c`，它会覆盖现有内容；请交由管理员管理现有站点账号。不要为了读取密码文件而开放整个 /root 目录权限。

在宝塔的已有 HTTPS server 配置中加入下面两项，位于 `location` 外：

```nginx
auth_basic "MemoryPet";
auth_basic_user_file /www/server/nginx/conf/memory-pet.htpasswd;
```

不要只放进 `location /`，否则单独的 API location 未必受保护；检查其他 include 或 location 没有 `auth_basic off` 或 `satisfy any` 等绕过规则。完整 server 内配置片段见 `backend/deploy/nginx-public.conf.example`。只合并当前站点对应块，不覆盖证书及宝塔校验目录，也不能重复定义 location。

API 代理应使用真实 Host，保持 Origin 和 Sec-Fetch-Site 不变：

```nginx
location ^~ /pet-api/ {
    proxy_pass http://127.0.0.1:8797/api/;
    proxy_set_header Host $host;
    proxy_set_header Authorization "";
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 300s;
    proxy_send_timeout 300s;
}
```

此处清除的是已经由 Nginx 验证过的站点 Authorization，避免再向 Python 传递入口账号；不是清除 Origin 来绕过来源校验。

HTTP Basic 必须配合有效 HTTPS 或 SSH 加密隧道，不能在明文公网 HTTP 上输入站点密码和业务 Key。当前 `http://81.71.39.10` 仅作为用户现有来源的匹配示例；正式使用请在宝塔为入口配置有效 TLS，并将下一节来源改为最终 HTTPS 地址。也可继续使用 DEPLOY.md 的私有 SSH 方案。

Nginx 鉴权指令依据：[Nginx HTTP Basic 官方文档](https://nginx.org/en/docs/http/ngx_http_auth_basic_module.html)。本地没有安装 Nginx，本次未代为创建密码、配置证书或重载服务器。

## 3. 合并后端白名单

在现有 config.local.toml 中合并以下分组；不存在时可新建仅含本分组的文件。保留原有模型、MemoryOS 和数据库配置。已有 `[server]` 时修改该节，不能重复添加。

```toml
[server]
allowed_hosts = "81.71.39.10"
allowed_origins = "http://81.71.39.10"
```

上面精确匹配当前 HTTP 入口。若最终入口是 `https://pet.example.com`，应改成：

```toml
[server]
allowed_hosts = "pet.example.com"
allowed_origins = "https://pet.example.com"
```

如确实需要同时保留多个入口，两个字段均可写逗号分隔的字符串。Host 不含协议、端口和路径；Origin 必须包含协议，非默认端口必须显式填写。禁止 `*` 和通配域名。默认本机地址仍保留，健康检查不会受影响。所有配置修改后须重启后端。

仍沿用优先级：环境变量 > config.local.toml > config.toml。对应环境变量为 PET_ALLOWED_HOSTS、PET_ALLOWED_ORIGINS；若部署环境设置过它们，须核对是否覆盖了文件。本次没有修改环境文件或真实配置。

## 4. 重启和验收

如果使用 systemd，由管理员重启该服务。如果使用新版 start.sh，同时更新 start.sh 与 start_service.py 并保留原有 Conda 路径和 ENV_NAME="memory"，然后在实际后端目录执行 `bash start.sh restart`。脚本会核验进程归属、等待原进程退出，再启动新进程，停止失败则取消重启。旧版脚本没有 restart 命令，须先按[停止与重启说明](../服务停止与重启/API接口文档.md)更新启动文件；不要按端口批量杀进程。

服务器本机检查应为 200：

```bash
curl --fail http://127.0.0.1:8797/api/health
```

假设最终 HTTPS 入口为 pet.example.com，无站点凭据访问应为 401：

```bash
curl -I https://pet.example.com/
curl -I https://pet.example.com/pet-api/health
```

提供站点用户名后，curl 会交互询问密码，健康检查应为 200：

```bash
curl --user petowner --fail https://pet.example.com/pet-api/health
```

通过浏览器打开同一入口并完成站点登录，再使用原有文字聊天流程。白名单拒绝返回中文 403，站点密码不正确由 Nginx 返回 401；两者不能混淆。长期记忆连接及模型仍需单独验证，健康 200 不代表上游可用。

本修复只涉及后端与代理配置，不需要重新打包前端，前提是已部署产物的 API_BASE_URL 确实为 /pet-api。
