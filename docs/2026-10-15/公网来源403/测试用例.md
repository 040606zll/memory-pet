# 测试用例

复现与回归文件：tests/backend/bug_fix/2026-10-15/公网来源403/test_public_access.py。

| 场景 | 预期 |
| --- | --- |
| 默认配置，公网 IP Host | HTTP 403，保留“此服务仅允许本机访问” |
| 默认配置，本机 Host | 健康接口 200 |
| 配置当前 IP 与 Origin | GET 健康、浏览器 POST 正常通过 |
| 错误 IP、相似域名、额外后缀 | 403 |
| Origin 的协议或端口不匹配 | 403 |
| 域名大小写及默认端口 | 规范化后匹配 |
| 本机 IPv4、IPv6 和开发端口 | 保留兼容 |
| 重复 Host、Origin 或包含 cross-site 的多值头 | 403 |
| URL 用户名、无效端口、无效 IPv6、带路径或控制分隔的输入 | 拒绝且不抛未处理异常 |
| 不允许的来源配合伪造 X-Forwarded-Host 或回环 Host | 仍拒绝 |
| 配置通配符、空项、无协议、带凭据或路径 | 启动失败，中文提示且不回显敏感值 |
| 本机配置和环境覆盖 | 沿用原优先级 |
| 原连接、模式隔离、记忆链路和启动脚本 | 全量回归保持通过 |

自动化使用临时配置、独立数据库和上游替身；默认配置路径也在 tests/backend/conftest.py 中隔离，不读取开发者密钥。Nginx 入口匿名 401、授权 200 及浏览器真实操作由服务器部署人员按《服务器更新步骤.md》验收，本地环境没有 Nginx，不能将策略单测当成目标服务器鉴权验收。
