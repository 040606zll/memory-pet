# 模型 JSON 模式偶发空正文

现象：真实供应商在“不要挥手，也不要眨眼，只安静陪着我”的正式对话请求中，返回 HTTP 成功但 message.content 只有约27个空格。服务按契约返回中文502，未把空正文保存为宠物回复。

实况根因：这是供应商 JSON Output 空内容问题，不是情绪枚举失配。master 捕获了不含凭据的模型 content 验证这一点。DeepSeek 官方也说明 JSON模式可能返回空内容，并建议明确 JSON 输出示例和调整提示词：https://api-docs.deepseek.com/guides/json_mode/

处理：system prompt 增加合法 JSON 示例、第一字符{和末字符}、即使安静请求也需一句简短非空正文，temperature降到0.2。仍只有一次真实调用；空正文、JSON非法、输出截断依然返回502。用户可以明确重试同一幂等编号，不能自动重试或生成假回复兜底。

另一个独立的稳健性改进：有效正文出现未知可选情绪时归为neutral，动作严格筛已实现白名单，候选仅保留有效字符串；这样可选元信息不会误丢真实正文。这不属于此次纯空白实况的根因。

动作边界：happy只指开心微笑，移除了把跳舞、转圈、跳跃当作happy的别名。模型提示明确未实现动作要坦诚说明暂时不会，不能借用其他动画伪装实现。

自动化验证覆盖空content、纯空正文、截断、未知情绪、非法动作、否定动作。真实prompt缓解效果以master重新启动后实际模型请求的结果为准；不能用替身测试证明供应商永不返回空正文。


## 真实差分定位与已验证的最小修复

复现命令：`python tests/backend/bug_fix/2026-10-14/模型JSON空白/compare_real_provider.py --baseline --modes json_object --repeat 1 --assert-valid`。首次已运行：HTTP200、stop、16空格、0有效字符，脚本退出1。脚本只读MemoryOS根.env中的LLM参数，不打印或保存凭据。对指定本地会话只读最近20条消息，实际4条；偏好使用master真实链路报告中的已确认雨声/疲惫偏好。

先列出的可证伪假设：1）response_format强制模式会造成空白，省略后会恢复合法JSON；2）多个system消息覆盖规则，合并会恢复；3）最后用户“安静”语义主导输出，最后user层再明确结构会恢复。每次只改一个变量，其余模型、温度、上下文、记忆、用户原句保持相同。

| 请求差异 | 强制JSON合法次数 | 省略response_format合法次数 | 观察 |
| --- | --- | --- | --- |
| 原始两条system和原始user句 | 0/3 | 0/3 | 强制模式13–16空格；省略模式有真实中文正文但不是JSON |
| 仅合并两条system | 0/3 | 0/3 | 仍为空白或非JSON，未修复 |
| 仅在最新user消息加入JSON字段提醒 | 3/3 | 3/3 | 均为真实JSON回复，actions为空 |
| 最终生产代码，保留response_format并加入提醒 | 3/3 | 未再次测试 | 非空真实JSON，耗时0.569/0.583/0.848秒 |

因此没有采用仅省略response_format：该方式原本不满足接口结构。最小修复仅在发送给模型的最新user消息前明确“生成完整json，含reply/emotion/actions/candidates”。用户原句仍完整保留，召回query和本地用户消息不变，没有额外模型请求、失败重试或正文兜底。观察证明这个提示变更对当前真实案例有效；供应商内部导致忽略system规则的机制没有证据，不能声称已证明。

先写针对真实请求构造缝隙的回归并观察失败，再修改；完整41项单元回归通过，97%覆盖。另通过原会话真实上下文重复3次，均通过。原始失败、两种模式、单system、用户层提醒及最终生产代码证据分别保存为同目录`模型JSON*真实对比.json`与`模型JSON修复后真实回归.json`，原始报告未覆盖。调试脚本留在明确的bug_fix诊断目录，无临时调试日志进入产品。

最后由master重启真实后端并执行完整训练→确认→召回→跨会话→否定动作链路，确保最小修复没有影响其他路径；不能仅以本差分实验宣布整个产品完成。
