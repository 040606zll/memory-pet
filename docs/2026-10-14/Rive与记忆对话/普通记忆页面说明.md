# 普通记忆对话页面

2026-10-14，前端独立页面，地址由主代理挂载为 `/memory`。

## 使用流程

1. 在“连接设置”填写 MemoryOS 地址、用户 ID、API Key，以及大模型地址、名称和 API Key。连接状态只依据后端验证结果。密钥不写入浏览器存储。
2. 在“写入记忆”模式发送长期有效的信息。对话中的候选可以修正、拒绝或确认；未经确认的候选不当作长期记忆。
3. 点击“确认并写入”。只有后端返回 `confirmed` 和非空真实记忆编号才显示成功；异常保留候选供原内容重试。成功状态可展开查看编号，编号按钮打开独立右侧记忆抽屉并搜索该内容。
4. 点击“新会话测试召回”。页面创建一个 `surface=memory`、`mode=chat` 的全新会话，清除当前聊天历史，不自动发送任何测试消息。
5. 输入需要先前信息的问题。回答下方默认只显示引用数量，展开可检查记忆编号、来源和正文。重复编号只显示一次。

示例按钮只填入草稿。普通助手不使用宠物人格、动作、等级或虚假的已训练数据。左侧只读取普通助手会话；记忆抽屉覆盖右侧，不改变中央对话的宽度。

## 接口约定

响应统一为 `{code,message,data}`，前端通过共享 `api.js` 解析中文错误。

| 接口 | 普通页面用途 |
| --- | --- |
| `GET /api/status` | 获取真实连接状态 |
| `POST /api/connection` | 通过共享普通表单连接与验证服务 |
| `GET /api/sessions?surface=memory&page=N&limit=20` | 左侧普通助手会话分页 |
| `POST /api/sessions` | 参数 `surface:memory`、`mode:training/chat`、`title` |
| `PATCH /api/sessions/{id}` | 更新模式 |
| `GET /api/sessions/{id}/messages?page=N&limit=100` | 先读取总页数，再加载最新页；前向读取更早消息 |
| `POST /api/sessions/{id}/chat` | 参数 `content`、`request_id`、`pet_name:记忆助手`，普通人格由服务端 surface 选择 |
| `PATCH /api/sessions/{id}/candidates/{id}` | 修正 `content` 或拒绝 `status:rejected` |
| `POST /api/sessions/{id}/memories/confirm` | 参数 `candidate_id`；收到真实编号才确认成功 |
| `GET /api/sessions/{id}/memories?page=N&limit=20&q=...` | 真实长期记忆搜索与分页 |

## 请求与交互保护

- 发送中禁止重复提交、模式切换和历史切换；取消通过 AbortController 传给共享传输层。
- 失败保留原完整请求；“重试消息”复用同一个 `request_id`。切换模式后把失败内容还原草稿，清除旧模式的重试请求。
- 每个操作绑定页面版本和会话 ID；卸载、重连或新会话后，旧响应不得回写。即使传输忽略取消，聊天、确认、创建和历史安装仍检查取消信号。
- 历史默认加载最后一页，更早消息按编号去重前插并保留滚动位置。会话列表和长期记忆独立分页，搜索响应有独立版本保护。
- Enter 发送，Shift+Enter 换行，输入法组合阶段 Enter 不发送。输入上限 4096 字符。
- 错误和加载状态为中文；已确认编号为真实服务回执，未确认内容不显示“已写入”。
- 移动端会话列表折叠；记忆侧栏为非模态区域，可按 Escape 关闭并归还焦点。所有主要输入与图标按钮都有可访问名称。
